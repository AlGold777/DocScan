## Организация

Основной агент интегрирует камеру и OCR-движок. Изолированные изменения хранения/кодека/PDF делегируются. Проверки и сборки выполняют GPT-6 Luna/high. Полный прогон ведётся из копии проекта в /tmp, чтобы не менять существующие сборочные артефакты. Результаты сравнения и ограничения фиксируются здесь; синтетические страницы не выдаются за реальные фотографии. В доступных приложенных материалах нет набора реальных сканов с эталонной расшифровкой.

## Инженерные решения и результаты

* Исходник камеры привязан к ImageVersion съёмки, а не единственной записи Page: Undo пересъёмки не подменяет его новым кадром. Источники удерживаются в течение жизни страницы и Delete Undo, затем могут освобождаться штатным GC. Старые потерянные полные кадры предыдущих версий восстановить невозможно.
* Непустой hOCR тоже может оказаться частичным: после прерываемого распознавания его текст сверяется с кэшированным UTF-8 движка. При расхождении используется ResultIterator; если полной геометрии нет, сохраняется полный plainText без фиктивных рамок. Baseline совпавших строк переносится из hOCR.
* Синтетическая тень, fast/PSM3: ORIGINAL CER=1.000, LIGHTING=0.000, OTSU=1.000. В итоговом прогоне время 290/411/280 мс соответственно; на чистом английском изображении и мелком тексте качество не выросло, время увеличилось. Поэтому нормализация применяется автоматически только при неравномерном фоне. Диагностика проверяет яркие пиксели 48 регионов; выводы относятся к этому набору/эмулятору. Явные профили benchmark отключают автоматический выбор, чтобы сравнение оставалось честным.
* Для реальных примеров использованы первые десять testing-аннотаций [FUNSD](https://guillaumejaume.github.io/FUNSD/) (Jaume, Ekenel, Thiran, 2019), commit `8905aca92b3181853307e2880e3d6f71dee8e9f3`, SHA-256 dataset.zip `c31735649e4f441bcbb4fd0f379574f7520b42286e80b01d80b445649d54761f`. Это сканы форм, а не фотографии телефона. Метрики — multiset recall размеченных слов и чисел, без недостоверного предположения о глобальном порядке аннотаций.

## Воспроизведение сравнительного прогона

В отдельной копии проекта выполнить `python3 tools/prepare_ocr_benchmark_assets.py --project /путь/к/копии --with-real-scans`. Скрипт проверяет закреплённые SHA-256 трёх best-моделей и архива FUNSD, заполняет только AndroidTest assets. Production APK их не содержит. При отсутствии дополнительных assets пропускаются только сравнительные benchmark-классы, обычные регрессии работают без них.
