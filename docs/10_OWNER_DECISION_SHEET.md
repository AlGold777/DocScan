# DocScan — лист решений владельца для MVP

**Версия:** 1.0 · 2026-09-23
**Кто заполняет:** владелец продукта (Мария Гольдберг).
**Кто использует:** агент-исполнитель по плану `docs/09_MVP_EXECUTION_PLAN_FOR_AGENT.md`.
**Статус документа:** `AWAITING OWNER` — пока пункт не отмечен владельцем, агент считает его **не решённым** и не начинает зависящие задачи.

## Как заполнять

По каждому пункту поставьте `[x]` в одном варианте. Если выбираете «Иначе», напишите решение словами. Рекомендации подготовлены ревьюером (Claude) по UFS, Functional Map, FROZEN v1.2 и документам 06–08. Это **предложения**, а не решения: агент не имеет права применять рекомендацию без вашей отметки.

Пункты типа **FACT** решаются в два шага: сейчас вы утверждаете *метод и предварительные пороги*, после измерений агент приносит данные, и вы утверждаете итоговые числа.

После заполнения агент переносит каждое решение в `execution/decisions.md` с ID, датой и пометкой `Authority: Owner`, а новые правила — в `docs/11_UFS_DECISIONS_ADDENDUM.md` (задача T1.2 плана).

### DEC-Q — проверка на физическом телефоне без режима разработчика

**Решение владельца (2026-09-23):** «Мы будем проверять через установку APK и не будем заниматься переходом в режим разработчика».

Последствия, которые нужно подтвердить явно, так как это изменение приёмки относительно frozen-протокола (`02_…Spike_Protocol`, `04_PHYSICAL_QUALIFICATION_RUNBOOK`):

1. Gate Q в исходном виде (adb/USB, 800 + 6 000 + … + 4 100 автоматических прогонов на `DUT-X14U-01`) **не выполняется**. В `execution/tasks.json` он получает статус `SUPERSEDED BY DEC-Q`, а не `DONE`.
2. Взамен используются три вида доказательств:
   - автоматические тесты на эмуляторе (`DEV`, через adb на компьютере разработчика; телефон для этого не нужен);
   - встроенная в приложение **«Самопроверка»**: скрытый экран, который прогоняет сценарии в изолированной песочнице (крэш рабочего процесса, восстановление, OCR, PDF) и сохраняет отчёт; вы отправляете отчёт кнопкой «Поделиться»;
   - ручная приёмка на Xiaomi 14 Ultra по пошаговым чек-листам, которые агент готовит к каждой сборке.
3. Что теряется: нет автоматической статистики на реальном телефоне (p95/p99 задержек, сотен повторов крэш-сценариев). Итоговый MVP будет заявлен как «проверен вручную и самопроверкой на Xiaomi 14 Ultra, HyperOS <версия>», без заявления «квалифицирован по протоколу v1.1».
4. Frozen-документы не редактируются; отступление фиксируется только в `execution/decisions.md`.
5. Gate A (review-переход к продукту) остаётся: его выполняет ревьюер по DEC-REVIEW до начала продуктовых этапов.

Не продлевают: просто открытие приложения или просмотр, а также фоновая обработка, OCR и восстановление. Это разрешает CONFLICT-01 в пользу FROZEN §F-15 и INV-14.

## Группа G. Решения владельца по интерфейсу и режиму камеры (v0.4.238..v0.4.243)

### DR-27 — разделение жестов по эскизам нижней ленты (v0.4.238)
**Решение владельца:** одиночный тап по карточке переключает выбор страницы для включения в PDF (или фокус); двойной тап открывает полноэкранное окно детального просмотра и редактирования (`showPageViewer`).

### DR-28 — современный тулбар редактирования без текста (v0.4.243)
**Решение владельца:** с кнопок ROTATE, CROP, ADJUST в окне просмотра/редактирования полностью удаляются текстовые подписи. Используются только современные векторные иконки (`ic_rotate_right`, `ic_crop`, `ic_tune`).
- [x] Принято и реализовано в v0.4.243

### DR-29 — обновление кнопок действий в окне просмотра (v0.4.243)
**Решение владельца:** кнопка «Переснять» переименовывается в `ReClick`, «РАСПОЗНАТЬ» — в `ReOCR`, кнопка «УДАЛИТЬ» заменяется на минималистичную контурную иконку корзины (`ic_delete_trash`).
- [x] Принято и реализовано в v0.4.243

### DR-30 — увеличение размера просматриваемых эскизов на +17% (v0.4.243)
**Решение владельца:** размер карточек эскизов в нижней ленте увеличивается на 17% по высоте и ширине: с 88×64 dp до 103×75 dp (в ячейках ленты и кэше загрузчика).
- [x] Принято и реализовано в v0.4.243

### DR-31 — динамический размер зоны просмотра распознанного текста (v0.4.243)
**Решение владельца:** зона OCR не фиксируется на жесткой высоте, а плавно расширяется в зависимости от объема распознанного текста от минимального значения (42 dp) до максимального (130 dp) с внутренним скроллом для длинных текстов. Окно просмотра (`InsetDialogHost`) адаптируется динамически (`WRAP_CONTENT`).
- [x] Принято и реализовано в v0.4.243

### DR-32 — режим камеры «Документ» с автодетекцией и коррекцией перспективы (v0.4.243)
**Решение владельца:**
1. С правой стороны от кнопки «Пуск» размещается кнопка-тумблер «Документ» для включения/выключения режима.
2. В реальном времени поверх видоискателя отрисовывается зеленый полигон-оверлей (`DocumentOverlayView`) по найденным 4 углам документа.
3. При съемке с активным режимом «Документ» к снимку автоматически применяется перспективная коррекция (гомография OpenCV), выравнивающая документ в ровный прямоугольный лист.
- [x] Принято и реализовано в v0.4.243
